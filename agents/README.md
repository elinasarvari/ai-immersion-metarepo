# Agents

Every agent is a separate subagent: its own session and context, started by a workflow step or from chat, that reads its inputs, writes its own files and hands back a short reply. None of them talks to another; they pass work through files in `specs/<NNN-feature>/`.

| Agent | Does | Writes | Skills |
|---|---|---|---|
| [`architect`](architect/architect.agent.md) | plans the feature: technical details, decisions (ADRs), scope; hands product, policy, cost and amendment questions to the decision-maker | `plan.md`, `research.md`, `data-model.md`, `contracts/`, `decisions/`, `scope.json`, `brief.md` | `architecture-plan`, `architecture-decision`, `architecture-capabilities` |
| [`spec-clarifier`](spec-clarifier.agent.md) | answers the spec's open `[NEEDS CLARIFICATION]` questions independently, on the evidence; leaves open only what a person alone can know | the answers in `spec.md` (`## Clarifications`, automated session), `clarifications.json` | — |
| [`decision-maker`](decision-maker.agent.md) | decides the open ADRs independently, on the evidence; never amends rules | open ADRs' decision, `decisions/README.md`, `decisions/auto-decisions.json` | — |
| [`spectator`](spectator/spectator.agent.md) | test strategy, after the plan and decisions and before the tasks: every requirement mapped to named test cases, each with its lane and repo, so the tasks step writes their tasks in its one pass | `test-plan.md` | `test-strategy` |
| [`compliance-reviewer`](compliance-reviewer/compliance-reviewer.agent.md) | checks the implementation against the constitution, rules, ADRs, security and data rules | `review/compliance.md`, `review/compliance.json` | `compliance-review` |
| [`integrator`](integrator.agent.md) | merges `origin/main` into the feature branch when another feature landed; resolves textual and semantic clashes by intent (main wins unless that breaks this feature's requirements) | the merge commit, `decisions/ADR-…-align-with-main.md`, `review/integrate.md` | — |
| [`backend-reviewer`](backend-reviewer.agent.md) | senior code review of `benefit-be` | `review/code-benefit-be.md`, `review/code-benefit-be.json` | — |
| [`frontend-reviewer`](frontend-reviewer.agent.md) | senior code review of `benefit-fe` | `review/code-benefit-fe.md`, `review/code-benefit-fe.json` | — |

An agent is a `*.agent.md` file: frontmatter (`name`, `description`) plus its rules (role, scope, responsibilities, evidence, editing, communication). An agent with its own procedures keeps them next to it in `<agent>/skills/`. Both tools find agents and skills through links generated by `scripts/sync-copilot.py`.

**Who runs them.** In a feature run, the workflow engine (`workflows/benefit-feature/workflow.yml`) is the orchestrator: it starts each agent as its own step, in parallel where the work is independent (the three reviewers), and checks each agent's files by script before the next starts. In chat, the main session starts them as subagents the same way, for example the three reviewers in parallel through the `review-changes` skill.

## Conventions every agent follows

Keep them short; they're read on every run.

1. **Read only what you need.** Rule files come from the map in `project-rules/README.md`, for the paths you touch, not all of them. Read diffs, not whole repos. Read a file once.
2. **Write to files; reply briefly.** The full output goes in the files listed above. The reply is ≤10 lines: the verdict, the counts, and the file paths.
3. **Every status file is JSON:** `{"blocking": <n>, "verdict": "PASS|FAIL", "findings": [{"id","severity","file","line","rule","summary"}]}`. The workflow reads only this.
4. **Cite, don't quote.** `repo:path:line`, rule IDs (`TW-3`), principles (constitution V), `ADR-…`, `FR-…`. Never paste rule text or large code blocks.
5. **Only real findings.** Confirmed in the code, with the input or state that triggers it. No style points that linters already enforce.
6. **On a re-review, review the change.** If `review/snapshot.json` and your earlier result exist, review `wf.py delta <feature_dir> <repo>` (the change since your last review) and re-check the earlier findings; don't redo the whole review. The workflow reruns a review only when it has no result, still blocks, or its repo changed.
7. **Never edit outside your files.** No agent edits code unless its skill or agent file says so (the integrator does, to resolve a merge).
