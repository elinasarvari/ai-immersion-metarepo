# Agents and roles

| Who | Kind | Does | Writes |
|---|---|---|---|
| `architect/` | role (skills) | plans the feature: technical details, decisions (ADRs), scope | `plan.md`, `research.md`, `data-model.md`, `contracts/`, `decisions/`, `scope.json` |
| `quality-engineer/` | role (skills) | test strategy: every requirement mapped to test cases and QA tasks | `test-plan.md`, test tasks in `tasks.md` |
| `compliance-reviewer/` | role (skills) | checks the implementation against the constitution, rules, ADRs, security and data rules | `review/compliance.md`, `review/compliance.json` |
| `backend-reviewer.agent.md` | agent | senior code review of `benefit-be` | `review/code-benefit-be.md`, `review/code-benefit-be.json` |
| `frontend-reviewer.agent.md` | agent | senior code review of `benefit-fe` | `review/code-benefit-fe.md`, `review/code-benefit-fe.json` |

A **role** is a folder with `rules/behavior.md` and `skills/`; whoever runs one of its skills takes on the role. An **agent** is a `*.agent.md` file. Both tools find them through links generated by `scripts/sync-copilot.py`.

## Conventions every role and agent follows

Keep them short; they're read on every run.

1. **Read only what you need.** Rule files come from the map in `project-rules/README.md`, for the paths you touch, not all of them. Read diffs, not whole repos. Read a file once.
2. **Write to files; reply briefly.** The full output goes in the files listed above. The reply is ≤10 lines: the verdict, the counts, and the file paths.
3. **Every status file is JSON:** `{"blocking": <n>, "verdict": "PASS|FAIL", "findings": [{"id","severity","file","line","rule","summary"}]}`. The workflow reads only this.
4. **Cite, don't quote.** `repo:path:line`, rule IDs (`TW-3`), principles (constitution V), `ADR-…`, `FR-…`. Never paste rule text or large code blocks.
5. **Only real findings.** Confirmed in the code, with the input or state that triggers it. No style points that linters already enforce.
6. **On a re-review, review the change.** If `review/snapshot.json` exists, review `git diff <snapshot>` and re-check the earlier findings; don't redo the whole review.
7. **Never edit outside your files.** Roles and reviewers don't edit code unless their skill says so.
